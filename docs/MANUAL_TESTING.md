# Методика ручных испытаний mav-voice-gcs

Документ описывает ручную проверку приёмника MAVLink-телеметрии с голосовым
сопровождением по всем пунктам технического задания. Методика рассчитана на
инженера, впервые разворачивающего стенд: установка описана шаг за шагом.

- Испытуемое изделие: приложение `gcs-tts` (этот репозиторий).
- Источник телеметрии: ArduPilot SITL (ArduCopter), MAVLink на UDP 127.0.0.1:14550.
- Автоматический аналог этой методики: `scripts/integration.sh` (11 проверок);
  ручная методика подтверждает те же пункты «глазами и ушами» оператора.

## 1. Стенд

Допустимы две конфигурации:

| Конфигурация | ОС | Звук |
|---|---|---|
| A | Ubuntu 22.04 / 24.04 (нативно или VM) | напрямую |
| B | Windows 10/11 + WSL2 Ubuntu 24.04 | через WSLg (PulseAudio) |

Минимальные ресурсы: 2 ядра CPU, 4 ГБ RAM, ~8 ГБ на диске (ArduPilot ~3–5 ГБ,
Qt ~1,5 ГБ). Все команды ниже выполняются в терминале Ubuntu.

## 2. Подготовка стенда (однократно)

Проверка звука (в конфигурации B звук должен быть слышен на Windows-хосте):

```bash
espeak-ng -v ru "Проверка голосового модуля"
```

Если звука нет, но команда завершилась без ошибок — испытание можно проводить
в режиме записи WAV (см. п. 4.3), фразы проверяются по логу и файлам.

### 2.2. Qt 6.5+

В репозиториях Ubuntu Qt ≤ 6.4, а по ТЗ нужно 6.5+. Стандартный путь — aqtinstall:

```bash
python3 -m pip install --user --break-system-packages aqtinstall
~/.local/bin/aqt install-qt linux desktop 6.5.3 gcc_64 -O ~/Qt
```

Если `download.qt.io` недоступен из вашей сети (aqt падает на скачивании
контрольных сумм), Qt ставится вручную с любого зеркала, например:

```bash
B=https://mirrors.ocf.berkeley.edu/qt/online/qtsdkrepository/linux_x64/desktop/qt6_653/qt.qt6.653.gcc_64
S=6.5.3-0-202309260341
curl -fLO "$B/${S}qtbase-Linux-RHEL_8_4-GCC-Linux-RHEL_8_4-X86_64.7z"
curl -fLO "$B/${S}icu-linux-Rhel7.2-x64.7z"
sudo mkdir -p /opt/qt && sudo 7z x -y -o/opt/qt ./*.7z
sudo chmod -R a+rX /opt/qt
```

## 3. Запуск стенда (перед каждым сеансом)

Три терминала (или `tmux`):

**Терминал 1 — симулятор** (работает до конца сеанса; выход `Ctrl-C`):

```bash
cd ~/ardupilot
./build/sitl/bin/arducopter --model quad --speedup 1 -I0
```

**Терминал 2 — консоль управления бортом** (MAVProxy):

```bash
mavproxy.py --master tcp:127.0.0.1:5760 --console
```

**Терминал 3 — испытуемое приложение**:

```bash
cd <каталог-репозитория>
~/build/mav-voice-gcs/gcs-tts --config config/gcs-tts.ini
```

Откроется окно: режим, состояние ARM, батарея, высота, скорость, канал,
сообщ/с, кнопка «Статус», «Озвучка: вкл», лог событий. В консоли приложения
видны строки `[announce] …` — озвучиваемые фразы.

> Перед каждым новым сеансом полезно сбрасывать состояние симулятора:
> `rm -rf /tmp/gcs-sitl-root` и запускать arducopter из этого каталога
> (`mkdir -p /tmp/gcs-sitl-root && cd /tmp/gcs-sitl-root`), тогда eeprom
> будет чистым и поведение воспроизводимо.

## 4. Тест-кейсы

Каждый тест: предусловия → шаги → ожидаемый результат. Фразы ниже должны
прозвучать и появиться в логе окна. Общее предусловие всех тестов — стенд
из п. 3 запущен, в окне горит «СВЯЗЬ ЕСТЬ».

### Т-01. Приём телеметрии

| | |
|---|---|
| Цель | Приложение подключается к SITL и принимает поток |
| Шаги | 1. Запустить стенд по п. 3. 2. Наблюдать окно 10–15 с |
| Ожидание | Через 1–3 с после запуска MAVProxy: «СВЯЗЬ ЕСТЬ» (зелёный), «сообщ/с» > 30, в консоли `[app] запрошен стрим сообщений у борта 1/1`; первая фраза «Режим полёта: стабилизация» |
| Критерий | Связь не пропадает; «ошибок парсинга» не растёт |

### Т-02. Статус по горячей клавише (на земле)

| | |
|---|---|
| Цель | F2 озвучивает высоту/скорость/заряд |
| Шаги | 1. Нажать F2 в окне приложения (или кнопку «Статус»). 2. Повторить через 1 с и через 5 с |
| Ожидание | Фраза вида «Высота 0 метров. Скорость 0 метров в секунду. Заряд батареи …» (заряд может отсутствовать — см. Т-06); повтор через 1 с подавлен антиспамом (в логе «подавлено антиспамом»), через 5 с — озвучен |
| Критерий | Хоткей и кнопка дают одинаковый эффект |

### Т-03. Смена режима полёта

| | |
|---|---|
| Цель | Озвучка смены режима |
| Шаги | В MAVProxy: `mode GUIDED`, затем `mode LOITER`, затем `mode RTL` (пауза 10 с между командами) |
| Ожидание | Фразы: «Режим полёта: наведение», «Режим полёта: лойтер», «Режим полёта: возврат в точку взлёта»; поле «Режим полёта» в окне меняется синхронно |
| Критерий | Все три смены озвучены и отображены |

### Т-04. Антиспам повтора события

| | |
|---|---|
| Цель | Одно и то же событие не чаще раза в N секунд |
| Шаги | В MAVProxy быстро: `mode GUIDED`, через 2 с `mode LOITER`, через 2 с `mode GUIDED` |
| Ожидание | Первые две смены озвучены; третья — в логе «смена режима: GUIDED — подавлено антиспамом (10 с)» и НЕ озвучена (в `gcs-tts.ini` по умолчанию `mode_change_sec = 10`) |
| Критерий | Подавление видно в логе; через 10 с повтор команды снова озвучивается |

### Т-05. Arm / Disarm

| | |
|---|---|
| Предусловие | EKF готов (в MAVProxy `arm throttle` не выдаёт PreArm; готовность наступает через ~30–60 с после старта SITL) |
| Шаги | 1. `arm throttle`. 2. Убедиться, что моторы вращаются (в SITL — по консоли/mavexplorer). 3. `disarm` |
| Ожидание | «Внимание! Моторы запущены» / «Моторы остановлены»; в окне ARMED (красным) → DISARMED (зелёным) |
| Критерий | Оба перехода озвучены |

### Т-06. Батарея: пороги warning / critical

По умолчанию SITL не отдаёт процент заряда (BATT_MONITOR=4), поэтому тест
переводит борт на монитор с интегратором тока и малой ёмкостью — процент
начинает реально падать, и приложение проходит оба порога.

Предусловие: тесты Т-01…Т-05 выполнены (arm больше не понадобится).

Шаги:

1. Остановить приложение (Терминал 3), запустить его с тестовым конфигом
   (пороги: warn 60 %, critical 45 %):

   ```bash
   ~/build/mav-voice-gcs/gcs-tts --config config/gcs-tts-integration.ini
   ```

2. В MAVProxy настроить батарею и перезагрузить борт:

   ```
   param set BATT_MONITOR 5
   param set BATT_CURR_PIN 12
   param set BATT_CAPACITY 10
   reboot
   ```

   MAVProxy сам переподключится. Если не переподключился — перезапустить его
   (Терминал 2). Приложение переподключится автоматически.

3. Наблюдать поле «Батарея» в окне: процент должен появиться и убывать
   (потребление электроники ~десятки секунд на 10 мА·ч).

Ожидание: при пересечении 60 % — «Внимание! Заряд батареи низкий: N процентов»;
при пересечении 45 % — «Критический заряд батареи! N процентов. Требуется
немедленная посадка»; цвет поля «Батарея» жёлтый → красный.

Критерий: обе фразы прозвучали, дребезг на границе порога не плодит повторы
(гистерезис: повтор возможен только после восстановления выше порога+5 %).

Примечание: если проценты падают слишком быстро и между кадрами SYS_STATUS
порог проскакивается — увеличить `BATT_CAPACITY` (например, до 30) и
перезапустить борт с чистым eeprom.

### Т-07. STATUSTEXT уровня WARNING+ дословно

| | |
|---|---|
| Цель | Входящие предупреждения озвучиваются дословно |
| Шаги | 1. До готовности EKF (сразу после перезапуска SITL) выполнить `arm throttle`. 2. Отказ arm — и PreArm-тексты. 3. Альтернатива/дополнение: `param set SIM_BATT_VOLTAGE 10.5` |
| Ожидание | Дословные фразы, например: «Критическое событие! PreArm: Need Position Estimate», «…PreArm: Battery 1 low voltage failsafe»; заметные (Notice, sev 6) сообщения типа «Calibrating barometer» НЕ озвучиваются |
| Критерий | Тяжёлый уровень — дословно, лёгкий — тишина |

### Т-08. Высота и скорость в статусе (полёт)

| | |
|---|---|
| Предусловие | EKF готов, GPS 3D Fix (команда `gps status` в MAVProxy) |
| Шаги | 1. `mode GUIDED`. 2. `takeoff 20`. 3. Дождаться набора ~20 м (поле «Высота»). 4. Нажать F2. 5. `land`, после касания — F2 ещё раз |
| Ожидание | В полёте: «Высота 19–21 метров. Скорость … метров в секунду…»; на земле — высота около 0 |
| Критерий | Значения в фразе совпадают с окном с точностью до округления |

### Т-09. Мьют

| | |
|---|---|
| Шаги | 1. Нажать «Озвучка: вкл» → кнопка станет «Озвучка: выкл». 2. Сменить режим в MAVProxy. 3. Нажать F2. 4. Включить озвучку обратно и сменить режим |
| Ожидание | Пока мьют: фразы не звучат, в логе «✕ отброшено…» или «озвучка выключена»; после включения — озвучка возобновляется |
| Критерий | Приём телеметрии при мьюте не прерывается («сообщ/с» не падает) |

### Т-10. Очередь TTS не блокирует приём

| | |
|---|---|
| Цель | Долгий синтез не мешает телеметрии |
| Шаги | 1. Устроить «шторм» событий: несколько быстрых смен режимов + PreArm-тексты (arm без EKF) + статус по F2 подряд. 2. Следить за полем «сообщ/с» во время речи |
| Ожидание | «сообщ/с» не проседает заметно во время говорения (речь идёт в отдельном потоке); очередь ограничена (`queue_limit = 16`, лишние фразы отбрасываются с записью в лог) |
| Критерий | Ни одного «замораживания» окна; задержка фраз допустима, потеря телеметрии — нет |

### Т-11. Конфигурируемость порога антиспама

| | |
|---|---|
| Цель | Интервал N секунд берётся из конфига |
| Шаги | 1. В `config/gcs-tts.ini` установить `mode_change_sec = 30`. 2. Перезапустить приложение. 3. `mode GUIDED`, через 15 с `mode LOITER` (обе озвучены), ещё через 10 с `mode GUIDED` |
| Ожидание | Последняя смена подавлена («подавлено антиспамом (30 с)»), т. к. с последней озвучки прошло 25 с < 30 с |
| Критерий | Вернуть конфиг обратно (10) |

## 5. Режим без звука (WAV)

Если на стенде нет аудио, приложение запускается с переменной окружения
`GCS_TTS_WAV_DIR` — каждая фраза дополнительно пишется в WAV:

```bash
mkdir -p /tmp/gcs-wav
GCS_TTS_WAV_DIR=/tmp/gcs-wav ~/build/mav-voice-gcs/gcs-tts --config config/gcs-tts.ini
# проверить: ls /tmp/gcs-wav  (по одному wav на фразу), воспроизвести:
aplay /tmp/gcs-wav/*.wav
```

Критерий прохождения тестов в этом режиме: фраза есть в логе окна И
соответствующий WAV-файл создан.

## 7. Известные ограничения

- Процент заряда в SITL доступен только после переключения `BATT_MONITOR=5`
  (шаг Т-06); на реальном борту с корректным мониторчиком процент приходит
  без дополнительных настроек.
- Хоткей F2 действует, когда окно приложения в фокусе (требование «минимальное
  окно», глобальные хоткеи X11 вне рамок ТЗ).
- При одновременном запуске нескольких копий приложения порт 14550 достанется
  только первой (сокет с ShareAddress, но пировать будет первый откликнувшийся).
